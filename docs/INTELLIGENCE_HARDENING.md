# Trained retrieval and operational hardening

This describes Phase 10–12 behavior. The default remains deterministic lexical coverage. Optional trained adapters are implemented, but no trained weights or live paid model were executed during development. Fabricated vectors test transport and authorization; they provide no semantic-quality evidence.

## Trained embeddings

`EMBEDDING_PROVIDER=disabled` is the default. `local` runs Sentence Transformers in an isolated Python subprocess against an operator-provisioned, immutable local directory. Install `backend/requirements-embeddings.txt` deliberately in a separate environment after reviewing its dependency resolution. That optional runtime and its transitive dependencies were not installed or fully audited here. It is not part of baseline CI. No runtime download, Hugging Face token, remote code, pickle or PyTorch `.bin` loading is allowed. Safetensors, an artifact SHA256 and allowlisted Transformer/Pooling/Normalize modules are required. CPU/wall deadlines apply; Linux adds an address-space bound. Resource limits can reject larger models.

Configure `EMBEDDING_MODEL` (operator model identifier), `EMBEDDING_REVISION`, `EMBEDDING_DIMENSIONS`, `EMBEDDING_LOCAL_PATH`, and `EMBEDDING_ARTIFACT_SHA256`. The artifact digest hashes sorted relative filenames, each followed by a NUL byte and its file bytes. Changing any file changes identity. Use a directory writable only by the operator; the digest does not replace artifact trust or protect against a malicious operator changing files while loading.

`openai` additionally requires `EXTERNAL_EMBEDDINGS_ENABLED=true` and the separately provisioned `OPENAI_API_KEY`. The lazy SDK client calls the genuine embeddings endpoint with explicit dimensions, a 15-second timeout and zero hidden retries. No call was made here. Workspace owners must separately consent to sending indexed text; each external search or answer request separately requires query transmission consent. These calls may incur provider costs. External service retention is outside local erasure controls.

Owners build an index from Documents. Trained scope includes current authorized tasks, decisions, document passages and imported GitHub records; historical decision revisions require explicit inclusion. Generated messages/activity are excluded from trained indexing. Native changes, additions, model/revision/artifact/dimension changes, epoch changes and permission revocation invalidate reuse through complete source-set and source fingerprints. Old character indexes remain compatible.

Jobs allow 64 sources, 16 inputs per batch, four calls, 2,000 UTF-8 bytes per source prefix and 64,000 input bytes per job. The byte cap bounds tokenization above without a tokenizer dependency; measured provider usage is recorded. Capacity/budget excess fails visibly. Leases are 150 seconds for trained jobs; retries require a fresh explicit request, a one-minute cooldown, and at most three attempts per source snapshot/model (per epoch/model for character indexes). Shared database quotas cap external embedding calls at twelve per minute across HTTP and worker processes. Queries are at most 200 characters. Source truncation can miss information.

The existing character index remains limited to 200 current document passages and is labeled character similarity, not a trained model. Its worker batches are bounded too.

`ranking=trained` uses reciprocal-rank fusion; `ranking=semantic` returns trained similarity candidates, with lexical fallback when an index/provider is unavailable. These explicit API modes never change the default. Filters intersect a fresh authorized SQL eligibility set, including status/time/history/archive filters; pagination and oversized eligibility sets safely fall back. No similarity score represents confidence. Membership, epoch, source set and fingerprints are checked again after provider latency; errors never return a stale pre-call result snapshot.

## Grounded answers and agents

Ask workspace offers lexical or explicitly requested trained evidence. Saved-answer idempotency binds retrieval mode. Citation allowlists and source fingerprints still gate generation and every later read. Unsupported lexical questions abstain. Lexical blocker questions first retrieve tasks explicitly marked Blocked; change questions retrieve recorded activity in the last 24 hours. The evidence scope is displayed; these rules do not detect all implicit blockers or external changes. Model interpretations remain separately enabled, cited and bounded. Citation validity does not prove entailment or truth.

Agents can link up to eight document/import/historical-decision references in addition to native inputs. The picker can explicitly search trained evidence. Selected sources enter context and fingerprints, propagate to child runs/retries and take priority in bounded research evidence. Workers do not call embedding or generation providers while executing local contracts. Native task proposals and report publication still require exact current-owner approval and atomic receipts. Nothing marks work Done automatically.

## Evaluation and live verification

`python backend/evaluation/pilot.py --output docs/evaluation-phase10.json` runs the existing forty frozen developer-created holdout cases against legacy, coverage, focused and character hybrid retrieval. Development prompts remain in `pilot_development.json`; neither set is independent human judgment. Reported API timings include SQL/source validation on a tiny synthetic workload, not a production benchmark. Character hybrid regressed on this holdout; coverage remains default.

With a separately provisioned local model, `python backend/evaluation/pilot.py --offline-trained --output /tmp/real-model-evaluation.json` additionally runs pure trained similarity and trained hybrid on the same synthetic corpus. It does not download weights or open an original database. This can be CPU intensive. External paid evaluation is intentionally excluded from this full holdout command. Real-model comparison remains unverified until the operator runs it. No independent participants or human quality judgments were fabricated.

Private GitHub ordinary reads retain a maximum ten-minute cached permission window. Sync revalidates selected installation/repository identity and persists rotated grants before later reads. The owner's Revalidate private access button performs only fixed-host permission GETs; model transmission requires freshness within thirty seconds. A failed check revokes credentials, cancels syncs and invalidates derived evidence. Permission changes cannot be observed instantly without a new check; this is a stated residual window.

Each successful sync atomically records a checkpoint with its connection version, time, record count and created/updated/unavailable/unchanged counts. Stable IDs and unchanged versions survive reconciliation. Failed/incomplete pagination never advances it. These are bounded full snapshots with incremental upserts, not remote delta streaming or resumable page cursors; large repositories may hit the explicit pagination capacity.

`python backend/live_private_check.py --workspace-id ID --connection-id ID --test-repository owner/test-repository --allow-live-selected-test-repository` is an unexecuted operator harness for an already-connected authorized test repository on a loopback backend. It prompts for a Parallel login, checks source access, revalidates permissions, waits for the operator to remove only that test repository from the App installation, and verifies denial. It never registers an App, reads CLI GitHub tokens, authorizes repositories, logs source bodies or performs repository writes. Supply no original project as a fixture. Live GitHub verification remains unperformed because no authorized App/test connection was supplied.

## Account recovery

Recovery is disabled unless a development/test operator sets an absolute `RECOVERY_OUTBOX_PATH`. Production rejects this local delivery mode. HTTP recovery requests return the same 202 message and queue shape for known/unknown addresses; the worker performs delivery. This reduces request timing differences but is not a constant-time guarantee. Shared peer and HMAC-address quotas limit abuse. No raw address is stored in counter keys.

Tokens are 256-bit random values, SHA256-only in the database, expire after thirty minutes and work once. New delivered tokens supersede earlier in-flight/delivered tokens of the same purpose. Resets revoke all sessions and all other recovery tokens. Login/password verification, token consumption and issuance serialize on the user row, including PostgreSQL. Reset does not automatically log the user in. Verification grants no workspace role or privilege and legacy accounts are not implicitly verified.

The delivery abstraction receives plaintext only for a private local outbox: directory 0700, exclusive files 0600, no symlink directory, no HTTP token/outbox endpoint, no token response or application logs. Tokens are pasted into password-type fields from this private channel. Local verification is a development simulation, not proof of real mailbox ownership. No SMTP/email was sent. Treat outbox files as secrets and remove expired files through operator retention; database expiry does not erase files or backups.

The worker expires stranded/old recovery jobs after thirty minutes and removes recovery records after seven days. Expired sessions are removed only seven days after expiry. Pending expired device secrets are cleared; terminal invitation IDs and project/audit history remain. These operational policies never automatically delete messages/tasks/decisions or retention receipts.

## Worker health, recovery and retention

An independent heartbeat thread reports process liveness during long jobs. Liveness does not prove queue progress or successful work. Queue errors log only a fixed event and queue number, back off that queue thirty seconds, and allow others to progress. Existing bounded job leases and explicit attempts recover interrupted work. Supervision templates still require operator installation; no deployment occurred.

The owner-only Members panel exposes derived-content erasure, document content erasure, imported-cache erasure, and workspace closure. A signed five-minute preview binds actor, workspace revision, scope, target, epoch and counts. Any intervening workspace mutation or expired/tampered/replayed plan requires review again. The user types `ERASE REVIEWED CONTENT` before executing the exact plan. No retention action runs during migrations.

All scopes conservatively erase **all workspace derived content**, including run context/outcomes, approval/proposal copied payloads, saved claims/evidence, generated messages and vectors, and cancel pending work. Source scopes also erase the selected document's entire content history or selected imported cache, preserving tombstones/IDs/hashes. Closure applies to all document/import content, revokes pending invitations/device authorization, clears connection credentials, cancels work and denies normal workspace access. Late worker/model results cannot restore erased content.

Human-authored messages, task/decision history, manually authored questions/objectives and approved native tasks remain. Approval hashes, resource/receipt IDs, timestamps and execution receipts remain as audit exceptions; erased payloads cannot be reconstructed from hashes. The owner can read `/workspaces/ID/retention/receipts` after closure. This is scoped content erasure, not complete account deletion, guaranteed physical media erasure, external-provider deletion, or automatic backup expiry. Native human text and old backups require separately reviewed handling.

## Real PostgreSQL restoration drill

`APP_ENV=test DATABASE_URL=.../parallel_test python backend/tests/postgres_restore.py --container DISPOSABLE_CONTAINER_ID` requires an explicitly disposable PostgreSQL 16 service. It creates two exclusive UUID-named synthetic databases, migrates/seeds documents and exact approved native task execution, writes a new 0600 custom-format `pg_dump`, restores into the second empty database with `pg_restore --exit-on-error`, compares every table/row and receipt, verifies source unchanged and repeats migration on the restored database. Passwords travel through environment, not command arguments. Cleanup drops only databases successfully created by this invocation. It never restores into `DATABASE_URL` or an existing database and uses no original backup.

The local run actually passed with 32 tables and 24 rows; the recorded checksum and result are in `postgres-restore-phase12.json`. CI runs the same drill plus new recovery/embedding/retention tests in exclusive PostgreSQL schemas. Synthetic restoration does not prove a production recovery-time objective, key escrow, offsite backup policy or operator disaster readiness.
