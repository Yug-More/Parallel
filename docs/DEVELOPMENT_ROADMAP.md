# Development roadmap

Runtime configuration, hardening and external limits: [trained intelligence and operational hardening](INTELLIGENCE_HARDENING.md). Earlier milestone sections below describe their original scope.

## Implemented foundation

**Phases 0–1B:** audit/remediation, private workspace authentication, messages/activity, invitations, ownership/membership, tasks/dependencies, revocable sessions, migrations and collaboration browser/CI coverage. Unsafe legacy external execution remains disabled.

**Phases 2–3:** versioned source-linked decisions, supersession, deterministic retrieval/continuity, synthetic evaluation, leased local status/dependency/handoff contracts, bounded delegation/retries and exact owner-approved report publication.

**Phase 4:** bounded UTF-8 text/Markdown upload, durable extraction, immutable passage/revision provenance, archive invalidation; owner-authorized public read-only GitHub imports with durable sync/backoff/revocation; current/historical decision/document retrieval; measured coverage-based lexical ranking; persisted extractive answers and separately enabled citation-validated model interpretation. See [Connected knowledge](INTEGRATIONS.md). At that historical checkpoint PDF/private authentication and semantic infrastructure were not yet implemented; current support is described below. No live paid model verification is claimed.

**Phase 5:** local task planner, context researcher and two-child delivery coordinator alongside existing contracts. Exact owner approval can create a bounded sequential native task plan, with current-context/authority checks, at-most-once atomic task creation and receipts. Planning analyzes existing blockers/decisions and splits explicit user steps; it is not general model planning. Research quotes authorized evidence and abstains without matches. No arbitrary coding, external writes or automatic Done status.

**Phase 6:** a live overview with tasks/blockers/decision counts, approvals, knowledge, changes, recent runs, next actions and worker health; integrated documents/connections/questions/native approvals; real desktop/mobile workflows; readiness, safe request IDs/logs, bounded bodies, worker recovery and a tested SQLite backup utility. Existing collaboration journeys remain covered. Production hosting is not implemented or claimed.

## Phases 7–9 implementation

Extractable PDFs with page provenance and subprocess bounds; separate development and 40-query developer holdout labels; optional SQL-backed provider/index infrastructure with a shipped local character adapter and lexical fallback; phrase/current-state ranking behind an explicit option. Grounded answers expose conservative conflict/history warnings.

GitHub App device authorization supports selected read-only private repositories, encrypted expiring user grants, renewal, bounded pagination/upserts and permission expiry/revocation. This path is fixture-tested, not live-authorized. Existing agents add evidence-bound issue triage and exact native receipts; optional cited model interpretation remains a separate explicit action.

First-run guidance, source focus restoration, index/private-flow UI, persisted desktop/mobile browser journeys and automated interaction metrics complement shared request counters, queue rotation, an exclusive-path restore utility and an operator supervision template. These are engineering foundations; see [pilot boundaries](PILOT_READINESS.md).

## Next combined development cycle

1. Obtain independently adjudicated retrieval and real participant usability evidence. Benchmark a genuinely trained optional embedding provider with consent, deletion/epoch tests and independently held-out labels; measure semantic gains before changing defaults.
2. Owner-configure and authorize a real selected-repository App pilot. Verify SSO, access loss, refresh renewal and larger repository behavior; add verified webhooks/cursor reconciliation only with bounded full-snapshot fallback.
3. Operate supervised services and encrypted backups in a controlled pilot, run PostgreSQL recovery and load/failure drills, and implement a reviewed production delivery adapter plus operational retention/backups. Private local recovery/verification and signed owner erasure/closure already exist. No public deployment is implied.
4. With explicit cost authorization, evaluate live model citation entailment and injection resilience. Expand approved native actions only where exact payload/version checks and independently verified receipts remain feasible.

## Release gates

Keep backend/browser/PostgreSQL coverage, both lexical evaluations, dependency audits, secret scanning, diagrams and setup instructions aligned. Report actual PR/CI results and operational gaps; local tests are not production, scale, model-quality or adoption evidence.
