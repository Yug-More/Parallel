# Development roadmap

## Implemented foundation

**Phases 0–1B:** audit/remediation, private workspace authentication, messages/activity, invitations, ownership/membership, tasks/dependencies, revocable sessions, migrations and collaboration browser/CI coverage. Unsafe legacy external execution remains disabled.

**Phases 2–3:** versioned source-linked decisions, supersession, deterministic retrieval/continuity, synthetic evaluation, leased local status/dependency/handoff contracts, bounded delegation/retries and exact owner-approved report publication.

**Phase 4:** bounded UTF-8 text/Markdown upload, durable extraction, immutable passage/revision provenance, archive invalidation; owner-authorized public read-only GitHub imports with durable sync/backoff/revocation; current/historical decision/document retrieval; measured coverage-based lexical ranking; persisted extractive answers and separately enabled citation-validated model interpretation. See [Connected knowledge](INTEGRATIONS.md). PDF/OCR, private GitHub authentication and semantic embeddings are not implemented. No live paid model verification is claimed.

**Phase 5:** local task planner, context researcher and two-child delivery coordinator alongside existing contracts. Exact owner approval can create a bounded sequential native task plan, with current-context/authority checks, at-most-once atomic task creation and receipts. Planning analyzes existing blockers/decisions and splits explicit user steps; it is not general model planning. Research quotes authorized evidence and abstains without matches. No arbitrary coding, external writes or automatic Done status.

**Phase 6:** a live overview with tasks/blockers/decision counts, approvals, knowledge, changes, recent runs, next actions and worker health; integrated documents/connections/questions/native approvals; real desktop/mobile workflows; readiness, safe request IDs/logs, bounded bodies, worker recovery and a tested SQLite backup utility. Existing collaboration journeys remain covered. Production hosting is not implemented or claimed.

## Next development cycle: evidence quality and operational readiness

1. Gather independently human-adjudicated retrieval/usability evidence. Current labels are author-curated; vocabulary and multilingual misses remain. Evaluate lexical indexing or optional embeddings only with correction/revocation tests and stated workloads.
2. Add PDF/OCR in a resource-isolated extraction process and private GitHub authentication with server-side scoped credentials, expiry and revocation. Add broader pagination only with explicit import budgets and deletion/restriction reconciliation.
3. Introduce fair queue scheduling, supervised workers, shared abuse limits, account verification/recovery, encrypted backups and measured restore drills. Define retention policies before larger team use.
4. Evaluate the optional model boundary with authorized live calls and independently judged citation entailment. Keep interpretation separate from accepted records; no provider compatibility/quality claim follows from fake-adapter tests.
5. Extend native proposals only where exact previews, versions, evidence, replay protection and atomic receipts remain enforceable. Any external write is a separate authorization/integration project with independently verified outcomes.

## Release gates

Preserve membership/source boundaries, migration data, historical contributors and exact commit identity. Keep backend/browser/PostgreSQL coverage, both lexical evaluations, dependency audits, secret scanning, diagrams and setup instructions aligned. Report actual PR/CI results and operational gaps; local tests are not production, scale, model-quality or adoption evidence.
